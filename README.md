# Private Equity and State-Dependent Hiring — replication materials

Code and result artifacts for *Private Equity and State-Dependent Hiring*. The paper links private-equity investments in Korean companies to monthly National Pension Service employment records and asks which targets respond: it finds that the hiring response is organised by the target's pre-deal hiring state, and that the larger hiring response among low-hiring targets appears in gross worker flows rather than in larger net employment gains.

## Start here — the notebooks render on GitHub

| Notebook | Contents |
|---|---|
| [`notebooks/01_main_tables.ipynb`](notebooks/01_main_tables.ipynb) | Tables 1–7 and Appendix Table F.4.1, regenerated and checked byte-for-byte against the paper's tables |
| [`notebooks/02_figures.ipynb`](notebooks/02_figures.ipynb) | Figures 1–4 and Appendix Figures A1–A2, regenerated and checked by SHA-256 against the paper's figure files |
| [`notebooks/03_traceability.ipynb`](notebooks/03_traceability.ipynb) | Every row of the claims ledger resolved against its artifact; artifact hashes checked against the manifest |

**Outputs are stored in the notebooks**, so every table and figure is visible on GitHub without installing anything or obtaining any data. Each notebook reads only the aggregate result artifacts in [`artifacts/`](artifacts/) — no licensed microdata is used or required.

The table and figure cells are **cut verbatim from `code/build/make_tables.py` and `make_exhibits.py`**, the scripts that generated the exhibits attached to the manuscript, so the notebooks cannot drift from the paper's code. The final cell of each notebook compares the regenerated output with the reference copy in [`paper_exhibits/`](paper_exhibits/) and raises if anything differs; the stored outputs show all 8 tables and all 6 figures identical, and all 345 ledger rows resolving.

To re-execute: Python 3.11+, `numpy`, `matplotlib`. Run from inside `notebooks/`, or rebuild the notebooks themselves with `python code/build/make_nb_p014.py`.

## How a number in the paper is traced

Every reported number has a row in `artifacts/CLAIMS_LEDGER_v4.csv` giving its value, interval, sample size, the artifact file, the JSON path inside it, the pipeline script that produced the artifact and that script's hash at run time. Notebook 03 follows every row. Rows marked `SUPERSEDED` belong to designs the paper no longer features (they are reported as robustness or in the appendix); they are kept so that every number ever reported remains traceable, and the corresponding artifacts are kept in `artifacts/` and flagged in the manifest.

## Verification run against the manuscript

`code/verification/` holds the three checkers that were run on the manuscript before submission. They need the manuscript files, which are not part of this repository, so they are included for transparency rather than for execution here:

- `verify_draft.py` — every number in the prose must exist in the ledger or an artifact; retired artifacts are excluded from the pool and values that appear only in retired artifacts are blocked.
- `assert_anchors.py` — each headline claim is pinned to the specific artifact it must come from, so a correct number attached to the wrong source is caught.
- `check_refs.py` — every section, table, figure and appendix reference resolves to an existing target.

## Pipeline

Scripts are numbered `i01` … `i69` in the order they were written; `CODE_INDEX.md` lists what each does and `HARNESS30.md` describes the harness conventions (both in Korean, the pipeline's working language). The shared loaders are `h30_common.py` and `h39_common.py`. Artifacts carry the generating script's relative path and hash in their `code` and `sha256_16` fields.
